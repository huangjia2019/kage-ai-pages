一步一步看设计
01
SDD 规约
规约先定义输入证据、输出 schema、引用要求、置信度阈值和质量检查。
规约即契约


02
文档接入
把修订版通知、历史基线和内部 AML/KYC SOP 作为不同证据源接入。
上下文分诊


03
语义差异
把长监管文本压缩成变化条款、义务、影响行和行动候选。
语义压缩


04
政策 RAG
用内部政策上下文支撑解释，并保留来源引用。
RAG 管道


05
影响报告
输出结构化合规报告：严重度、负责人、截止日期和判断理由。
提示链


06
质量门
引用不足、置信度低或高影响行动缺失时触发复核。
审批门控

模式映射
模式设计作用
上下文分诊先区分变化条款、基线文本和内部政策，再进入深层推理。


语义压缩把长文档压缩成义务、影响和行动，同时不丢掉证据链。


RAG 管道让结论落到检索到的政策和来源锚点上。


审批门控用置信度和影响半径决定 Agent 是否必须停止并升级。


可观测性 Harness把引用、置信度、质量检查和行动项显式暴露出来。


设计洞察
证据就是产品
真正有价值的不是一段摘要，而是从条款到影响再到行动的链路。


质量门决定自治边界
Agent 要知道什么时候可以继续，什么时候必须交给人复核。


SDD 让合规可执行
规约同时约束 prompt、代码、输出和评估。
