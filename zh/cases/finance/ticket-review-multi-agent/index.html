一步一步看设计
01
原始工单
输入仍然是混乱的运维对象：文本、优先级、组件、环境和用户信号。
上下文分诊


02
Parser Agent
解析器把自然语言转成结构化 JSON，后续节点只处理字段。
工具分派


03
Quality Agent
质量角色检查复现步骤、环境、预期行为和证据完整性。
对抗式审查


04
Knowledge Agent
知识角色检索历史工单，识别重复问题或已知事故。
RAG 管道


05
Merge 节点
并行结果汇总成一个决策状态：分数、风险、路由原因。
扇出/汇聚


06
人工复核
弱证据、重复或高优先级工单不会自动关闭，而是升级复核。
审批门控

模式映射
模式设计作用
交接链每个 Agent 拥有单一职责，并传递结构化报告。


扇出/汇聚质量检查和知识检索可以并行运行，最后再合并。


对抗式审查第二个角色专门挑战工单完整性和优先级声明。


RAG 管道历史工单知识作为证据检索，而不是让模型猜。


审批门控风险分层决定自动通过、要求修改或人工复核。


设计洞察
先拓扑，后 Agent
不要先堆 Agent，要先判断工作是顺序、并行还是复核门控。


JSON 是接口
协作表面不是自由对话，而是结构化状态。


风险路由才是产品
系统真正有用，是因为它决定什么可以流转、什么必须被看见。
