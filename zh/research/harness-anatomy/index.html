Harness 解剖 · 八大 agent 框架的横切分析

八个工业级 agent harness，放在同一张图上看。不是当框架来学，是当标本看。 这一页的核心是热力图——看每个 harness 选择把哪几格做深、哪几格留薄， 以及横切之后整个领域的轮廓。

这一页跟 双轴框架、 模式演进图、 范式演进时间线 并列。四者在四个尺度上问同一个问题—— 范式是工程师怎么看世界， 模式是某个范式里被命名的解法， 双轴矩阵是 agent 这个范式的结构解剖， 而harness就是这套结构在 2026 年的具体实现。 矩阵是地图，harness 是疆土。

怎么读这一页：下面那张热力图是中心。行是 harness， 列是认知功能，格子是 0-3 的覆盖深度。点任何一个框架名或任何一个格子， 右边会滑出详情面板——主循环位置、定位、在哪几格做得深。 名单不封闭——这套方法可以再加任何新框架。

覆盖热力图 · 8 harness × 7 认知功能

横看一行，看一个 harness 的轮廓。竖看一列，看整个领域哪些能力已经成熟 （行动列全亮 = 工业必备），哪些还是 2026 的投资前沿（治理列大半空白）。 颜色深浅代表工程深度，不是『有没有这个功能』。

画出这张热力图的五步法

上面这张图不是观点，是一个固定流程跑出来的结果。五步。每个框架两到三天， 可重复。矩阵里每一个格子都有源码文件 + 行号定锚，颜色深浅来自代码本身长什么样， 不是来自这个框架自己的宣传。

五个共同祖宗

把八个 harness 横着摆，会发现同样的五个工程思想在反复出现。没有一个是新的。 没有一个是 agent 专属的。它们是软件工程这五十年来攒下的东西， 只是从 agent 的角度看才像是新问题。

    这张热力图能看到的三件事

    第一，每个 harness 都有主循环，结构都一样——它们是『概率版本的收敛循环』。 第二，整个领域已经在『行动』上标准化了，差异都集中在其它六列。 第三，覆盖最广的那两家不是开发者工具——是个人 AI 和多 agent harness， 因为它们的需求把每一个认知功能都强行拉了进来。
