认知功能 × 执行拓扑

两条正交的轴。Agent 在做什么 × 工作长什么形状。相交之后，是 28 个命名模式落座的坐标系。

定义

一个 Agent 设计是两条轴的交点。认知功能是 agent 在试图做什么—— 感知、记忆、推理、行动、反思、协作、治理（7 类）。 执行拓扑是工作长什么形状——链式、路由、并行、循环、层级、编排（6 种）。 相交形成 7×6 = 42 格，28 格落有命名模式，14 格有意空白。

它如何改变设计决策

模式选型变成了坐标选型。"我们需要一个反思模式"是欠定的； "我们需要反思 × 循环，并配一个确定性的退出信号"是一次设计。 两个工程师都说"我们用 Plan-and-Execute"，可能指向两个不同的格子—— 行动 × 链式（线性 plan）或行动 × 编排（动态 replanning）—— 而这个选择会带来真实的架构后果。坐标让这些选择在变成生产 bug 之前就可见。

谱系

  • Christopher Alexander——模式作为正交的生成轴，不是一张清单
  • GoF (1994)——模式矩阵结构：创建型/结构型/行为型 × 类/对象
  • 云架构目录——Microsoft / AWS 参考架构按场景 × 拓扑组织

它不是什么

  • 不是框架的分类法。LangChain / AutoGen / CrewAI 是机制；矩阵讲的是你用这些机制组合出来的设计。
  • 不是 28 个模式的扁平清单。清单是矩阵的扁平化结果；矩阵才是源头。
  • 不是成熟度记分牌。格子之间没有高下，简单格子并不比复杂格子轻。
