签名概念

一小组在 Agent 工程对话里反复出现、但一直没有共享名字的判断句。 每个概念有一个固定 URL —— 这样后面的文章、演讲、讨论里可以指向它， 而不必每次重新解释。

  • 四层结构：这套工作每一层各自在做什么

    案例是参考资料。概念是认知基础。模式是通用语言。双轴矩阵是容器。元叙述——先读这一篇。

  • 模型在花钱，Harness 在控预算

    Agent 架构本质是不确定性下的有界资源分配。真正的设计工作发生在 Harness 里，不在 prompt 里。

  • 认知功能 × 执行拓扑

    两条正交的轴。Agent 在做什么 × 工作长什么形状。相交之后，是 28 个命名模式落座的坐标系。

  • 模式坐标

    没有坐标的模式名，是一个标签，不是一次设计决策。坐标让选择可被讨论、可被验证。

  • 成本即设计约束

    当模型被锁死、成本是硬约束时，模式选型本身就是设计。这正是工程判断该出现的地方。

  • 编舞不是一种拓扑

    编舞是跨拓扑的协调模式，不是六列里的第七列。精神上更接近 Teams 模式，而不是 Orchestrate 的反面。

新概念只在一个想法已经在三篇以上写作里反复出现、但还没有名字时才加入。门槛刻意高。
